## 3. 八项值得优先吸收的增量

### N01：把宿主捕获完整性纳入记忆质量

材料指出 wrapper、MCP、hooks 看到的事件不同，部分适配器只保存部分文字并省略工具结果。记住“执行过 pytest”不足以证明“测试通过”。已有 L0 信封描述保存后的来源，还不能证明宿主原事件完整送达。[接入差异](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/提取与接入专题.md:24)、[工具结果过滤](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/提取与接入专题.md:54)

建议在现有 capture 与集成包中定义版本化 `CaptureProfile`：支持的事件/API、角色、有序内容块、工具请求/结果、失败/取消、附件，及 `omitted_fields / omission_reason / capture_complete`。保存宿主 event ID → 规范消息 ID → source revision 的映射。捕获覆盖与抽取召回分别计量；无法取得宿主事件全集时，覆盖分母为未知。

同时补防回流协议：可信宿主标记注入记忆及原 revision/receipt；再次捕获时它是传播记录或上下文，不是独立新证据。assistant 成功声明与结构化执行回执分开；未知改写不能被重复次数认证。用户重新确认自身偏好仍可以构成新的合格表达。[回流边界](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/提取与接入专题.md:60)

**落点与成本：** P0 定金标准，P1 接入；每个宿主版本增加契约测试。优先验证纯工具响应、流式中断、多内容块和已注入记忆回流。不要采集不需要保留的内部推理或无限日志来追求虚假的“完整”。

### N02：补客户端游标与待发事件协议

材料中的稳定操作 ID、已确认前缀及 pending append 解决“信息如何到达服务端”，与服务端 L0+任务事务是两个边界。客户端 GET→拼接→replace 可能覆盖并发追加的轮次。[游标与确认](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/提取与接入专题.md:84)

建议复用已有捕获队列与 SDK，补 `producer_id + event_id/sequence + CaptureCursor + PendingSubmission`：保留未确认事件，可靠确认后才推进游标；区分完整历史重传、追加、新会话续段和来源修订。服务端追加使用稳定事件身份和原子追加/版本保护，不能以客户端无保护整文替换作为失败降级。

**落点与成本：** P2；增加客户端本地状态和断网/崩溃测试。outbox 也受保留与删除代次约束，不能在服务端擦除后靠旧待发内容复活。append 减少传输不保证模型成本严格等于新增文字成本。

### N03：区分去重、资源串行化和任务进度

材料将提交去重、claim 串行化和资源键串行化分开；运行中到达的新输入不能被当成重复工作吞掉。[任务协议](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/整理与生命周期专题.md:90)

建议在 `operations/` 明确 `dedupe_key`、`serialization_key`、`requested_through`、`claimed_through`。执行时固定本次目标，期间新输入更新待处理目标或产生后继任务；完成时若仍有未处理范围，必须继续调度。资源串行化降低同文档/同视图的无效模型竞争，但不能替代 CAS、租约栅栏和发布检查。

再区分暂缓与故障：配额/背压 `defer` 不消耗一般故障重试计数，但受总年龄、容量和费用限制；进度看实际提交单元，心跳不能无限刷新“有进展”。取消只停止后续工作时，回执必须列出已提交部分。

**落点与成本：** P2，P3/P4 接整理刷新；需要任务字段与公平调度测试。不能照搬依赖稳定 worker ID 或管理员恢复才能解除资源占用的边界。

### N04：把增量刷新补成 outcome 与水位状态机

V6 已有稳定块、输入权限、精确水位和失败保护；材料额外给出了 source query 改变转 full、无效补丁受限修复、成功 no-op 与补丁未应用的区别。[刷新分支](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/整理与生命周期专题.md:73)

建议记录 `definition_fingerprint`，覆盖 source query/filter、模板/schema、生成政策及输出范围。定义变更走 full 或显式兼容迁移，不能沿用旧主题的 delta 下界。结果至少区分 `applied / noop_verified / incomplete / apply_failed / retraction_unresolved`；只有实际完整处理的变化可以推进水位。零 edits 不能自动代表撤回已经正确处理。

**落点与成本：** P3 固定契约、P4 实现；full 更贵，可加入有总预算的结构化纠错步骤。继续使用 V6 提交序列/覆盖清单，不改成检索结果最大 updated_at。

### N05：提供按用途等待就绪的能力

材料明确区分来源受理、事实写入、Observation 与知识页完成；“可服务水位”是报告作者建议，不是应直接宣称 Hindsight 已有的统一 API。[分阶段就绪](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/整理与生命周期专题.md:108)

建议定义 `wait_until(receipt, target, deadline)` 或等价查询：`source_persisted / l1_decided / index_visible / observation_covered / view_covered`，返回目标水位、实际水位、未覆盖范围和失败/待决原因。等待绑定有限的目标提交序列，不等待持续移动的“全库最新”而永不结束。

`l1_decided` 不代表候选已认证为真；全部待核验也可能已完成本阶段判断。接收 token、发布 token 与各索引/派生水位须分开。截止时间到达返回可查询状态，不默认为取消任务或把空结果当索引完成。

**落点与成本：** P2 先做 L0/L1/索引，P3/P4 扩展派生；这可推进原审查 **R11**，目前仍是建议而非已经关闭该项。

### N06：让 trace 告诉我们证据在哪一步丢失

材料建议从原文、抽取、候选并集、精排装包到答案逐层核对最小充分证据。这比只调整 top-k 更能定位失败。[观察点与消融](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/检索与评测专题.md:243)

复用已有 trace，串联受权限保护的来源/断言修订：命中通道与排名、过滤/重排/装包去向及原因，形成 `capture_loss / extraction_miss / candidate_miss / guard_filter / rerank_loss / packing_loss / synthesis_error`。安全过滤成功不应计为检索失败；金标准也须按查询的授权与时间限定可用证据。

最小充分证据可以是“多项必须同时具备”，例如决定、变更日期和原因；不能只命中正确文档就算答题证据齐全。公开 trace 不显示无权来源的 ID、内容或存在性。

**落点与成本：** P0 定格式，随现有检索先接可用阶段；P5 扩展。成本在元数据和人工标注。消融须区分移除某一路结果与移除其他路径依赖的种子，图不使用与图不构建也应分组计成本。

### N07：补模型适配器的输入预算与分数语义

V6 全响应预算已比调研中的部分路径严格；还应检查实际送给 embedding、reranker、生成模型的输入，避免 Bundle 合规但模型把句尾否定截掉。[输入限长](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/检索与评测专题.md:41)、[tokenizer 与预算](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/检索与评测专题.md:316)

建议适配器声明 tokenizer/version、实际输入长度、最大上下文、输出预留、截断/拒绝策略及 truncation map；必要条件不能被静默截断。reranker 另声明 `score_kind` 与校准版本，组内相对排名不能直接套绝对相关性阈值；切换 provider 后阈值不兼容须显式处理。[评分合同](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/检索与评测专题.md:96)

embedding 索引还需绑定模型身份、版本、预处理及维度；相同维度不代表同一向量空间。更换模型须新代重建并校验，不能混用新旧查询向量与索引。[中文与模型迁移](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/学习报告.md:405)

**落点与成本：** P1 模型接口，P5 排序，P6 索引迁移；不照搬英语模型或配置数字。用长中文、标识符、emoji、尾部例外和 failover 验证。

### N08：把评测从“要求有指标”推进到能归因、能阻断退化

建议复用 `evaluation/`，维护两类 fixture：冻结来源/L1/索引构建输入以隔离检索变化；从原始事件重放以测端到端变化。两者同时需要，不能每次重抽取后把分数变化都归因于排序。[冻结检索基线](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/检索与评测专题.md:216)

固定 scorer 协议：必要/禁止来源、时间精度、当前/历史值、语气、可答性、拒答、系统错误分别计分；确定性断言优先，语义裁判另记录版本并人工抽查。使用实际项目预算，报告每类任务、重复运行分布和费用，不以大上下文成绩替代日常配置。

发布配置需要明确 `Recall@budget` 下限、允许退化幅度和任务效果要求；复用已有 release 验收器执行。无固定数值时列为未完成配置，不能仅凭“已报告变化”通过。这可推进原审查 **R13**，不表示本文已选定或验证生产阈值。

**落点与成本：** P0 优先建立场景和计分，P3–P5 各组件验收；首批可以使用下面的合成种子，随后扩展许可真实数据。新增整理与 Reflect 必须在相同预算、数据和答题模型下做对照。

## 4. 17 个事件、20 个检查项如何进入本项目

[实验说明](/Users/chenliang/Documents/ChatGPT/记忆/Hindsight_全面调研_2026-10-06/实验说明.md:3)明确数据是合成规格、未执行，不是可直接提交的 SDK 请求。已验证文件可解析、事件 step 为 1–17、问题为 Q01–Q20，包含四个检查点；这仅是格式检查。

| 题目 | 适合验证 | 适配重点 |
| --- | --- | --- |
| Q01–Q02 | 偏好及例外 | 保留条件与可信场景，不能把所有问题都简短化 |
| Q03–Q06、Q17 | 决策理由、计划更新、事件/提及时间 | 计划不等于完成；固定 valid/known 与可用来源；当前类型不支持时声明能力缺口 |
| Q07、Q19 | 成功声明对比执行证据、精确标识符 | 注入可信工具适配器测试回执；不能凭正文或 metadata.source_type 授权 |
| Q08–Q10 | 同名实体、跨范围隔离、引用中的指令 | 正文中的用户 ID 不直接成为认证身份，bank/tag 映射为宿主授权范围 |
| Q11–Q12 | 120→12 的更正 | 新来源修订及明确更正/解释替代，不按 document_id 覆盖旧系统历史 |
| Q13、Q16 | 来源族、转述、部分来源退出 | 转述不是独立验证；需先定义删除操作及副本真实处理谱系 |
| Q14–Q15 | 全部来源擦除后的跨层读取 | 验证 L0/L1/Observation/页面/Reflect/缓存及历史，不能只禁止“作为当前知识返回” |
| Q18 | 中英跨语言证据检索 | embedding、关键词、重排分别控制变量 |
| Q20 | 输入/输出预算诊断 | 单独统计实际费用/裁剪，不能混进问答正确率 |

需要特别校正四点：

1. **可信来源。** synthetic metadata 只是测试材料说明；认证身份、工具资格、scope 必须由 fixture 的可信宿主配置提供。
2. **真实阶段重放。** 在 baseline、更正、部分删除、全部删除后分别检查。后续补双时态矩阵，也不能用材料的 query timestamp 假装历史数据库状态。
3. **删除语义。** 将 delete_document 映射为明确 archive/retract/erase。Q16 中“转述仍可用”只有在它是仍获准保留的独立接入来源时才可能成立；若是继承原来源 processing 依赖的派生产物，就必须遵守 V6 擦除传播。
4. **证据及判分。** document ID 通过真实来源链映射为 evidence/source revision；禁止语义主张不是关键词黑名单。“旧120错误、现为12”不应因为出现120被误判失败。19项语义/隔离检查与1项预算诊断分开，不能自动汇成一个总正确率。

这些案例没有覆盖 V6 四项修订的全部并发和权限分支，应与第 25.6 节的 24 项验收联合规划，而非认为 20 题已经证明整个架构。它们也不能替代真实领域留出集。

## 5. 按业务需要后置的借鉴

| 项目 | 值得借鉴的部分 | 放在后面的原因 |
| --- | --- | --- |
| 多模态来源 | 有序 text/image/file、附件修订、图像区域/页/表格单元定位，区分视觉直读与解析文本 | 当前优先文本事实闭环；增加视觉成本和附件治理，需要真实业务输入验证 |
| 有界拆分恢复 | SplitPlan、父子覆盖与稳定定位、最小语义单元、总调用上限 | 先确保 strict/partial 状态清楚；最小块仍溢出必须失败/未处理，不能空列表伪成功 |
| 可逆归档与关系维护 | restore 后重查资格；内容/时间/实体编辑对各类关系的影响矩阵 | 与来源资格、终止边界及跨槽更正等未闭合项相关，需单独设计；不能恢复旧 ready 标志或旧因果边 |
| 便携迁移与克隆 | 包含 ID 映射、策略/依赖/删除水位的 manifest，隔离导入，校验再切换 | 属于 P6；不同于灾备，不原样重放旧在途任务/lease，也不承诺普通事务自动提供全局快照 |
| 页面预计算策略 | 按查询频率、刷新成本和过期代价决定是否预生成 | 热点项目手册可能合适；低频、强时效查询可能直接 L1 更经济，先测量再自动启用 |

## 6. 应继续坚持的项目选择
