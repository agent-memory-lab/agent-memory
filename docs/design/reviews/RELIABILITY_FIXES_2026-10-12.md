## 交付与历史语义

最终交付以仓储最后一个读取快照为校验时点。它剔除失效证据，不再次调用模型，不补入未经原有排序与打包流程处理的新证据。历史查询保持请求的 valid/known 坐标，同时仍遵守当前删除与作用域约束。正文、引用和返回诊断一起处理，避免只删除正文而保留失效来源标识。

经过可信政策提升到 USER 等更广作用域的 Claim，按 Claim 自身范围授权，并检查同租户来源仍存活；原始来源所在 session 不必等于当前 session。该提升只允许披露获授权的事实，不自动开放原文。保留此区别可避免交付校验破坏合法跨会话记忆。

持久化 retrieval trace 记录交付前的候选选择，新增记录明确标记 `delivery_stage=pre_delivery`；最终 bundle 的 `delivery_guard` 记录校验状态和剔除数量。二者不能混同为最终交付清单。自定义仓储未提供该校验接口时保留兼容性，并明确返回 `unsupported`，不宣称已有原生仓储的保障。

`AgentMemory.recall` 配置自定义 pipeline 时，也在返回前核验本地事实及本地来源。原生持有的 ID（含删除墓碑）不能伪装成外部知识；外部记忆引用本地来源时，仍需验证本地来源存活且可见。真正的外部内容保留配置的 resolver 授权责任，返回 `mixed_authorities` 及明确的外部校验边界，不能声称本地仓储重新验证了外部版本。

## 重试与升级

调度失败保留 pending，退避从 1 秒指数增长到最多 300 秒。自动 drain 只取到期任务，每个意图每批最多尝试一次；显式指定 event ID 的重试可立即执行，仍受租约 token 校验。宿主仍需定期调用有界 drain。失败意图不会被自动丢弃，也没有新增“达到次数即永久放弃”的策略。

SQLite 原表增加 `next_attempt_at`；PostgreSQL 使用增量迁移 `022_consolidation_outbox_retry.sql`。旧 pending 行立即可执行。记忆块旧 payload 缺少 `source_claim_ids` 时仍按既有 event-only 契约读取，不推断未知历史依赖。
