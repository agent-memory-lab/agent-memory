## 必须通过的验收矩阵

| 用例 | 对应设计 | 预期结果 |
| --- | --- | --- |
| 同 scope 两来源明确支持 locale=zh-CN | §16；R04 | 逐项依据/版本可追溯，来源族相关性不增加置信概率；生成一个明确表达的 facet |
| 不同主体、facet、会话/项目范围 | §16.1；R04 | 不误合并、不扩大受众/分组；跨 exact scope 首版拒绝 |
| 实际输入含未引用的受限背景 | R04-01/02/03 | processing 全量记录，输出用途/受众仍受该输入限制；仅删引用不能扩权 |
| 未登记许可、撤销许可、保留到期 | R04-04/06；R09-02 | 未授权正文不进整理器；现有产物立即安全阻断，旧 grant 不能续用 |
| 当前资格/条件/字段支持不足 | R01/R03/R05 | 不发布无条件或整体确定陈述；pending/contested 不冒充合格事实 |
| 首次空查询前或查询中新增成员 | R08-01/02 | 查询前已有 barrier；版本变化 CAS 拒绝旧 snapshot；重算能看到成员 |
| 准备期间/提交后新增同槽反例或冲突 | R08；N04-03 | 原产物立即 stale/invalid，不能因未引用新事实而继续 ready |
| 无关主体/谓词普通变化 | §17.2 | 不要求所有 facet 重建；保守 scope safety 失效另作明确报告 |
| 初次 L1 分批发布尚未闭合，随后 closure | stage-11；§17.7 | 初次未闭合来源不入该完整查询；closure 更新屏障并触发后继责任 |
| 来源修订/重处理/资格或终止更改 | R02/R05/R06 | 在原事务中推进屏障并使受影响当前产物不可用；新旧解释不混用 |
| 删除最后一个来源；完整零成员快照 | R04-04；N04 | 旧正文/历史/准备按擦除要求清理；facet 单元可合法完成零输出，不生成“没有偏好”事实 |
| 普通故障或预算截断表现为空 | §17.7/17.9 | incomplete/apply_failed，不当作完整零成员结果，不推进未处理范围 |
| 内容相同但许可/输入修订/query 代次变化 | N04 | noop_verified 重新证明依赖和安全；不凭文本 hash 跳过授权 |
| 未来生效、有效期结束；无任何新写入 | R01；§17.2 | 到 next_transition_at 读端直接阻断旧快照；队列延迟不导致过期交付 |
| 同 facet 两个 worker；运行中新工作 | N03-01/02/03 | 排他 serialization、随机 fencing；固定 claimed 集合与持久后继责任，有限目标不漂移 |
| 事务中途失败、产物提交前后 SIGKILL | T04/T24 | 修订、边、head、覆盖与证明整体回滚/提交；恢复复用确定输入，旧租约不能覆盖 |
| 构建快照/登记屏障/删除之间跨连接竞争 | R08/R09 | 通过同 scope 锁和 CAS 排序；既有来源/epoch/安全守卫不被新入口绕过 |
| scope 擦除及真实旧备份回放 | R10；stage-10 | 旧派生正文、历史、输入清单片段和任务不能复活；保留合法无关来源 |
