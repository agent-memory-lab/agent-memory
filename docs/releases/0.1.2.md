Agent Memory 0.1.2 is an Alpha maintenance release for validation and publishing.

- Release scans now fail when an archive member cannot be read or input exceeds the scan limit; damaged ZIP members can no longer silently produce a healthy report.
- All seven Python distributions include the complete Apache-2.0 license. Package gates verify archive content and source hashes, exercise independent installs, and check downloaded Release attachments before publishing the draft.
- Plugin compatibility preserves prerelease precedence instead of treating prerelease and stable versions as equal.
- Containers use Alpine 3.24 (musl), a pinned base image and hashed dependency locks, with pip/ensurepip removed from the final server. A candidate digest passes lifecycle and vulnerability checks before promotion; existing version/source tags cannot be overwritten by the new workflow and older versions cannot move latest backwards.
- Container checks cover persistent-volume restart after a committed write and forced termination, identity isolation, deletion across restart, and HTTP authentication. Python packaging is checked on 3.13 and 3.14.
- Linux also checks minimum direct dependency combinations on both Python versions. The PostgreSQL adapter now requires psycopg >=3.2.10, replacing an unusable old binary dependency floor.

The default memory packing strategy remains v2. These engineering checks do not complete independent real-model answer-quality, business fact-selection, or full-lifecycle cost acceptance. Earlier benchmark scores and the API budget remain unchanged.

Image: `ghcr.io/agent-memory-lab/agent-memory:0.1.2` for Linux amd64 and arm64. Pin the published digest for deployment. The image contains core and MCP with SQLite; optional adapters are supplied as separate wheel/sdist assets.

The release attachments contain seven wheels, seven source distributions, `release-manifest.json`, and `SHA256SUMS`.
