## 1. 本轮目标

交付一个可由宿主实际接入的记忆反馈闭环：宿主检索记忆、报告决策和结果，插件验证反馈、整理经验、产生候选，并按宿主策略评估和晋升。整个过程有来源、有版本、有预算，并能查询与回退。

最小演示从 SQLite 开始，基础功能无需外部模型或服务。PostgreSQL 使用同一契约完成真实后端验收。演示 Procedure 的运行结果由宿主提供，不能用插件自己生成的成功结论证明收益。

## 3. 范围与交付物

本轮包含反馈可信关联、SQLite 持久化、宿主接入、Episode/Procedure 证据传递、现有晋升状态机完善，以及一个确定性检索策略候选的评测和回退闭环。

训练和运行编排保留在最终路线。近期只预留评价版本、策略版本、轨迹关联及数据快照所需标识，不引入训练框架、GPU 依赖或通用调度平台。Graph、latent、控制台扩建和全自动跨任务调参不作为本轮交付条件。

最终交付应包括可运行的本地示例、迁移说明、统一反馈契约、自动化回归用例，以及明确列出通过、失败、跳过和环境缺口的验收报告。

## 4. 核心行为约定

反馈链路为 `RetrievalTrace -> DecisionRecord -> OutcomeEvent -> Evaluation/Reward -> Candidate -> Evaluation -> Promotion/Rollback`。是否新增领域对象由契约核对决定；优先复用已有 EvaluationReport。

记忆被返回和被使用分别记录。宿主未报告实际使用时标记 unknown，不能自动按全部使用处理。任务取消、超时、评价缺失和失败分别表达；不将未知结果转换为成功或零分。

每个引用都检查可信作用域和目标版本。奖励必须携带评价来源及定义版本；不同定义不能直接合并统计。反馈更正采用追加式替代关系，不原地篡改既有审计证据。

重复请求返回一致结果。乱序结果可进入有界的待关联状态，不能参与策略调整或候选晋升；超过保留期需产生可查询的终止原因。

记忆策略不能放宽访问权限、证据有效性和 Token 总预算。Procedure 晋升需要对应阶段的有效评价及宿主授权；影子与灰度的实际执行由宿主承担。

## 6. 最小完整演示

1. 宿主建立可信作用域并记录用户输入与工具事件。
2. 插件返回受预算限制的 MemoryBundle 和可关联的检索标识。
3. 宿主提交 DecisionRecord，明确实际使用的记忆或标记未知。
4. 宿主提交结果与版本化评价，重复提交不产生重复有效反馈。
5. 后台从完整且有效的反馈生成 Episode 和 Procedure 候选，保留来源及失败案例。
6. 宿主提供离线、shadow、canary 结果与审批，插件据策略完成晋升。
7. 新决策只使用作用域可见且生效的版本；回滚后使用兼容的旧版本。
8. 删除一个来源后，受影响的候选、反馈和检索结果同步失效或被清理，不能继续作为有效晋升依据。

该演示验证机制正确，不以演示数据宣称通用任务收益。

## 7. 插件化与资源约束

默认安装保持零第三方运行依赖。Evolution、模型调用和后台 worker 按需启用。关闭反馈扩展时，已有记忆写入和检索仍可运行。

轨迹记录优先存引用和必要元数据，不复制完整 MemoryBundle 或工具输出。查询分页、后台任务按批读取；缓存、并发和待关联队列必须有容量与过期策略。

M0 测量冷启动、空闲 RSS、检索峰值、反馈写入及整理峰值，在固定环境和负载下确定可执行门槛。M3 用相同条件对照。未测量前不承诺某个固定 MB 指标。

## 8. 验收方法

| 维度 | 必须验证 |
| --- | --- |
| 关联正确性 | 返回与使用区分、失效版本、更正反馈、未知结果处理 |
| 持久性 | 并发重复、事务回滚、重启恢复、旧数据库迁移 |
| 隔离与删除 | 认证上下文派生 scope、跨租户引用拒绝、派生证据删除传播 |
| 进化控制 | 评估者与审批者校验、禁止跳阶段、过期审批、部署失败补偿 |
| 轻量性 | 关闭扩展时基础能力、记录容量有界、分页和背压有效 |
| 跨后端一致性 | SQLite 与真实 PostgreSQL 对同一反馈契约给出一致行为 |
| 发布可靠性 | 无效路径、损坏归档、扫描中断或覆盖不完整均不能报告完整通过 |

测试从新功能单元测试到存储契约、跨包接入及端到端逐步开展。缺少真实 PostgreSQL 环境时，可以继续完成本地闭环，但 PostgreSQL 验收必须标记阻塞，不可用 mock 替代其通过证据。
